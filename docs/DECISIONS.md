## Infrastructure and tooling

- **2026-04-20:** SvelteKit adapter is `@sveltejs/adapter-static`, NOT `@sveltejs/adapter-cloudflare`. The site is fully prerendered with no server-side logic; Workers would be overkill.
- **2026-04-20:** Cloudflare Pages build output directory is `build/` (adapter-static default), not `.svelte-kit/cloudflare` (which was Cloudflare's suggestion based on their framework preset).
- **2026-04-20:** Hosting on Cloudflare Pages free tier. GitHub Actions free tier for daily cron. Total expected monthly run cost: £0 for infrastructure, ~£10 for domain + analytics.
- **2026-04-19:** Framework is SvelteKit with TypeScript and Tailwind. Vitest for unit tests, Playwright for visual regression (later phases).
- **2026-04-19:** Git authentication via SSH keys, not HTTPS-with-token. One-time setup, permanent silent auth.
- **2026-04-19:** Repo is private on GitHub during build-out. Flip to public later if we want the build-in-public story; SPEC.md stays local-only for now.
- **2026-07-09:** CI workflow added (`.github/workflows/ci.yml`): push + `workflow_dispatch`, `npm ci` → `svelte-kit sync` → `npm test` → `npm run build`. No Playwright browser install — unit tests don't need it, and it keeps the job under ~3 minutes. Per the 2026-06-09 audit's Milestone 0: until now no regression, however severe, could turn a check red before shipping to a live site with a public posting bot.

## Data pipeline

- **2026-04-19:** BTC price comes from stooq (ticker `btcusd`), same source as the metals and agri commodities. Not CoinGecko. One parser, one failure mode, one rate-limit regime.
- **2026-04-19:** BTC circulating supply is computed deterministically from block height using the known halving schedule. No API dependency — it's a pure function of the protocol's supply curve.
- **2026-04-19:** Stooq uses `.c` suffix (continuous contracts), not `.f` as some references suggest. Correct symbols: `hg.c`, `zw.c`, `kc.c`. Claude Code caught this during Phase 0.
- **2026-04-19:** Historical data range is 2013-01-01 onwards. Pre-2013 data is too thin across commodities to be useful. Accept that Pizza Day (2010-05-22) is outside the dataset — it becomes editorial content, not an interactive preset.
- **2026-04-19:** Forward-fill commodity values for weekends/holidays when BTC data exists; flag forward-filled dates in meta.json for the UI to show "(market closed)" subtly.
- **2026-04-19:** Daily refresh via GitHub Actions cron at 02:00 UTC. Data commits go straight to main, trigger Cloudflare redeploy automatically.
- **2026-04-25:** Stooq introduced an API key requirement for CSV downloads post-bootstrap. `STOOQ_API_KEY` is now required in `.env` locally and as a GitHub repo secret for the daily cron. URL construction appends `&apikey=${STOOQ_API_KEY}`; the same change applies to `bootstrap.ts` so a re-run remains possible.
- **2026-04-25:** `health.json` schema extended: each source entry now records `httpStatus`, `rowCount`, and a redacted `url` (apikey/api_key values replaced with `***`). The trigger was a five-day silent forward-fill caused by stooq's new auth requirement — the prior `{ "status": "forward-filled" }` payload gave no indication whether a source was rate-limited, broken, or simply quiet on a weekend.
- **2026-04-25:** Workflow guard: `fetch-daily` exits non-zero when *every* source returns 0 rows on a weekday (Mon–Fri UTC). Weekend forward-fill is expected and stays silent; the guard fires only on the "infrastructure has changed under us" signal so it surfaces as a red ✗ on Actions plus an email notification rather than another silent commit.
- **2026-04-25:** Data artifacts (`prices.json`, `meta.json`, `health.json`) live in `static/`, not `public/`. SvelteKit's `adapter-static` ships everything under `static/`; `public/` was being written to by the data scripts but never reached the deployed site. The deployed dataset had been frozen at 2026-04-19 since 22 April because of this — the cron faithfully committed updates to a directory the build ignored. `public/` removed entirely; scripts and workflow updated.
- **2026-04-25:** Date-picker bounds (`firstDate`, `lastDate`) come from `meta.json` via the page's prerender `load` function, not from a hardcoded value in the component. The previous hardcoded `'2026-04-19'` survived in the SSR HTML's `max=` attribute even after data updates, capping the picker to a stale date until client-side hydration ran. Build-time fetch from `meta.json` bakes the correct value into the prerendered HTML.

## Commodity catalogue

- **2026-06-11:** Pu-238 depicts the **oxide fuel (PuO₂), not the pure metal** — supersedes the 2026-05-04 pure-metal decision. Rationale: the site's copy talks about fuel, RTGs burn the oxide, and the oxide is what glows in every reference photograph; depicting the metal while describing the fuel was a register mismatch. `densityGPerCm3` changes 19.8 → 11.46 (theoretical density of PuO₂; real sintered pellets run 80–90% of theoretical — methodology page to carry the caveat). Illustrative ~$5,000/g pricing unchanged. Brand-voice line gains the word "fuel". Live-scene prototype renders it as near-black matte ceramic with mass-scaled thermal glow.
- **2026-04-20:** MVP core is 6 commodities: gold, silver, copper, oil_brent, natgas, uranium_fuel_pellet. Optional additions: platinum, coffee. Everything else deferred to Tier 2 post-launch.
- **2026-04-29:** Natural gas removed from the MVP — drops the core to 5. The "invisible substance made tangible via LNG carrier" framing was conceptually neat but adds a vessel sprite library exclusively for one commodity, and gas is a poor fit for the "things you can hold" thesis. Source feed (FRED `DHHNGSP`), commodity entry, mmbtu unit, MMBtu format case, mmbtu volume branch, tests, and price-data fields all removed.
- **2026-04-29:** Silver migrated to cube mode. Renders inherit gold's lighting rig, camera, HDRI, and procedural noise/bump structure; only the material differs (base 0.972/0.960/0.915, roughness 0.08 with procedural variation 0.05–0.12 for the mirror-polished feel). `scripts/blender/silver_cube.py` is the canonical pattern for the remaining metal cubes.
- **2026-04-29:** Gold cube re-rendered to a mirror-polish material spec. Base roughness lowered from 0.20 to 0.08; procedural roughness MapRange tightened from 0.15–0.28 (cast/satin LBMA feel) to 0.05–0.12 (premium-mint PAMP / Argor-Heraeus feel). Trigger: when silver landed using the tighter range, its front face read as more desirable bullion than the cast-feel gold rendered earlier in the same session — gold being the headline commodity, it should set the polish bar, not trail it. Lighting rig, camera, HDRI, base colour, and bump rig unchanged — only roughness moved. `assets/materials-reference.md` updated to match; this supersedes the 2026-04-25 "roughness 0.20 / 0.15–0.28" lock-in.
- **2026-04-20:** Wheat is fetched in Phase 0 and present in prices.json, but deliberately excluded from MVP rendering. Deferred to Tier 2. Data preserved so re-adding is zero data work.
- **2026-04-20:** No diamonds, ever. Non-fungible (4 Cs determine price), no public spot price (Rapaport is subscription-only), and the lab-grown revolution has made natural diamond prices chaotic. A site built on honest data shouldn't touch this market.
- **2026-04-20:** Curio cabinet (Tier 3) trimmed to 6 items: U3O8 yellowcake, rhodium, osmium, saffron, tritium, californium-252. Dropped: iridium (redundant with rhodium), vanilla (weak pricing), helium-3 (redundant with tritium), antimatter (caveats dominate), palladium (visually too close to platinum for MVP).
- **2026-04-20:** Uranium fuel pellet promoted from Tier 3 curio to MVP core commodity. It's the site's philosophical closer — "1 BTC ≈ 4,500 pellets ≈ power for 1,650 UK homes for a year" is the single most shareable frame on the site.
- **2026-04-20:** Uranium fuel pellet pricing is illustrative (~$20/pellet) based on WNA composite fuel cost methodology. Not a live market price. Clearly labelled `illustrative` in UI with sources on methodology page.
- **2026-04-20:** Illustrative-priced commodities live in `src/lib/illustrative-prices.json` with mandatory source attribution and as-of date. Separate from `prices.json`. Do not pretend they're live market data.
- **2026-05-04:** Launch commodity set reduced from 6+ to four: gold, silver, cocaine, Pu-238. Other commodities remain documented but flag inactive for MVP via new `mvpLaunch: false` field on Commodity interface. Uranium fuel pellet deferred post-launch; Pu-238 takes its philosophical nuclear-fuel slot. Reasoning: tighter launch scope means each commodity can be authored to portfolio quality rather than spreading effort thin across a fuller set; remaining commodities re-enter post-launch as the rendering and asset pipelines stabilise.
- **2026-05-04:** Cocaine treatment reverts from five-stage progression to single forensic-still + dynamic readout. The progression was the most editorially fragile commodity treatment specced; the pile stage in particular carried Scarface/glamour risk the brand voice ("honest, precise, slightly dry") couldn't absorb. A fixed forensic-evidence-room still + bold readout showing weight purchasable at the slider's BTC amount is more honest about what this commodity actually is on the site (an editorial provocation, not a like-for-like fungible commodity comparison) and consistent with the existing principle that at extremes the readout carries the truth.
- **2026-05-04:** Pu-238 added as fourth launch commodity, displacing the uranium fuel pellet at MVP. Cube-mode rendering like gold and silver, using **pure Pu-238 metal at 19.8 g/cm³** (denser than gold's 19.30; cube edges marginally smaller than gold for equivalent mass). The visualisation has the luxury of nothing spontaneously disassembling — pure plutonium metal at multi-kilogram mass would self-destruct from its own decay heat in reality, but the cube on screen is what the dial says it is. **Two additional layers scale with mass independently:** (1) a radiant glow keyed to blackbody emission temperature, with separate intensity and colour-temperature channels — intensity climbs faster than colour temperature, matching real incandescence physics; (2) an **opt-in Geiger crackle** synthesising real Poisson-distributed click events at a rate proportional to specific activity (~17 Ci/g for pure Pu-238, so click rate scales linearly with mass). Default off, persisted via `?audio=on` URL state. One-line brand-voice clarification mandatory and persistent: "Plutonium-238 — the radioisotope that powers spacecraft. Non-fissile, not weapons material." Pricing illustrative at ~$5,000/gram material cost (composite from DOE / NASA Planetary Science / Cassini OIG 1997 escalated to 2024). Fully-loaded program cost ~$100,000/gram cited separately on methodology page as contextual comparison.
- **2026-05-04:** Page render order at MVP locked: gold → silver → Pu-238 → cocaine. Metals frame the tour, Pu-238 is the philosophical apex, cocaine is the editorial close that sends the reader away thinking.
- **2026-07-09:** Cocaine's illustrative OG-share price corrected from $35/g to $30/g (`functions/_lib.ts`). The comment there already claimed the UNODC wholesale midpoint, but $30/g is the actual figure used everywhere else (`src/lib/illustrative-prices.json` `tiers.wholesale.pricePerKg: 30000`; the bot's pricing). $35 had no documented rationale — closest read is a hand-sync slip, not a deliberate purity adjustment, so it's recorded here as a bug fix rather than a superseding decision. Every cocaine OG card had understated the buyable quantity by ~14% relative to the page it links to. `tests/drift.test.ts` now pins this figure to its source so it can't silently re-drift.
- **2026-07-09:** The day-over-day weight-delta engine (`gramsPerBtc`, `nearestObject`, `pickVerb`, `formatGrams`, `computeDelta`) moved from `scripts/bot/deltas.ts` into browser-safe `src/lib/deltas.ts`, and its data (`scripts/bot/objects.json`) moved to `src/lib/delta-objects.json` — one copy instead of one per runtime, ending three separate `gramsPerBtc` re-implementations (`deltas.ts`, `run.ts`, `make-short.ts`). The X bot still runs unchanged via `npx tsx scripts/bot/deltas.ts`; the module is now also imported by the homepage's Daily Delta line (see State and UX, below).

## Rendering and visuals

- **2026-04-19:** Sprite-based rendering, not realtime 3D. Pre-rendered WebP stills per progression stage, CSS cube-root scaling, cross-fade transitions. Three.js hero scenes only as optional Phase 5 polish for one or two commodities.
- **2026-04-19:** No rotation of commodity objects. Static sprites only. Rotation adds complexity without product value.
- **2026-04-20:** Scale reference system: £1 coin at actual physical size (CSS mm units) always; 1.75 m human silhouette only when commodity displayed size >300 mm; text comparison cards for displayed sizes >5 m. No menagerie of mid-range reference objects (no bricks, cars, buses, whales as rendered sprites).
- **2026-04-20:** Two distinct volume computations: intrinsic material volume (mass ÷ density, for the readout strip) and visual stacking volume (derived from sprite's authored `realWorldWidthMetres` metadata, for display scaling). Related but never confused.
- **2026-04-20:** Asset production sequencing: attempt Claude Code + Blender MCP first. Hard deadline of one focused weekend. If quality doesn't reach portfolio bar, fall back to £2-3k Upwork/ArtStation outsource. Don't sink weeks trying to make MCP work if it's not clicking.
- **2026-04-24:** Gold progression expanded from 6 to 10 stages. Sub-gram stages: `dust` (flakes on coin, coin baked into sprite) and `nugget_cluster`. Coin-product stages: `coin`, `tube` (20 Britannias, fills gap between single coin and bar products). Bar stages: `small_bar`, `kilo_bar`, `good_delivery_single`, `bar_pyramid`. Institutional stages: `pallet`, `vault_multi_pallet` — tile mode. Stage thresholds are approximate; will be tuned when real sprites land.
- **2026-04-24:** `renderMode: "scale" | "tile"` introduced. Scale mode is the existing cube-root continuous scaling. Tile mode computes integer tile count + fractional trailing tile, with 5 authored fill-state sprites per tile (0/25/50/75/100%). Fractional fill provides continuity between integer counts.
- **2026-04-24:** Isometric projection from `bar_pyramid` (stage 8) upward; three-quarter below. Projection change uses 300 ms crossfade — geometry change reads as "zoom out to institutional view".
- **2026-04-24:** `capAtTiles` is per-stage, authored in `tileConfig`. Gold pallet: 80 tiles (an 8×10 grid on desktop, the mobile readability limit). Gold vault_multi_pallet: 60 tiles (compact 8×8). Chosen for mobile readability; will tune once stubs are visible.
- **2026-04-24:** `countTemplate` is per-stage opt-in (e.g. "{n} kilo bars", "{bars} bars across {pallets} pallets"). Stages where a count is meaningless (dust, nugget_cluster) omit it entirely. Avoids a brittle global formatter.
- **2026-04-24:** Readout strip promoted to primary continuity signal. Uses `font-variant-numeric: tabular-nums` to prevent jitter during drag. Mass, volume, and count always update per slider tick — when the sprite layer is momentarily static, the numbers must be moving.
- **2026-04-24:** Dollar value promoted to primary UI element: ~2× type size directly under slider. `$XX,XXX.XX` with locale-aware separators, secondary line with per-BTC price and date. Tabular figures. Second-most important number on the page after the slider value.
- **2026-04-24:** Stub sprites are flat-coloured SVG rectangles at correct aspect ratio (1:1 for three-quarter, ~1.7:1 for isometric) with stage label overlaid. Live in `static/sprites/{commodity}/_stubs/`. Renderer is agnostic to stub vs real sprite — same paths, same contract. Stubs generated by `scripts/generate-stubs.ts`.
- **2026-04-24:** `dust` stage suppressCoinRef: true — suppresses only the standalone £1 coin element. When stage 2 (nugget_cluster) takes over, the standalone coin returns at 23.43 mm via the unchanged CSS-mm path.
- **2026-04-25:** Reverses 2026-04-24 decision on the 10-stage gold progression. Dense fungible metals (gold, silver, platinum, copper, palladium, rhodium, osmium) are now rendered as a single cube of intrinsic substance volume against a cycling library of scale references from grain of sand to Empire State Building. More honest (true substance, not packaging), continuous (no stage transitions), and roughly halves the asset budget for the metals family. Stage transitions were the real wart — drag the slider through `tube → small_bar` and the eye sees a category change rather than a continuous quantity change. Cube + reference is monotonic.
- **2026-04-25:** Reverses 2026-04-24 decision on tile mode for gold pallets. `renderMode: "tile"` and the per-tile fill-state authoring approach remain in the schema for potential future reuse, but no commodity at launch uses them. The cube approach absorbs the institutional-scale frame — at multi-pallet quantities you get a meter-edge cube against the Empire State Building, which is more honest than a 60-tile grid pretending to be vault contents.
- **2026-04-25:** Scale reference library introduced as `src/lib/scale-references.json` with 19 entries spanning ~6 orders of magnitude (grain of sand at 0.5 mm to Empire State Building at 381 m). Cycling-library approach replaces the per-commodity human silhouette and £1-coin special cases for cube-mode commodities — `person` and `pound_coin` are now ordinary entries in the library, picked when the cube edge falls in their respective scale bands. Progression-mode commodities (silver, copper, oil, gas, fuel pellet, coffee) keep the standalone `HumanSilhouette` and `CoinReference` components for now; they migrate when their renderStyle flips.
- **2026-04-25:** Two visual vocabularies, internally coherent. Cubes for dense fungible metals; vessels and packaging for fluids and bulk solids (Aframax/VLCC/Q-Max for oil and gas, sacks/pallets/silos for coffee and grain). The fuel pellet keeps its existing per-stage progression — it's the philosophical closer of the tour and the stage transitions read as a feature there, not a bug. Vessel and bulk renderers stubbed in `PhysicalRep.svelte` until Phase 2c.
- **2026-04-25:** PBR material values for gold are authoritative in `assets/materials-reference.md`, not in `docs/SPEC.md`. The SPEC table held design-time guesses (roughness 0.12 for gold) which did not survive iteration; production values are roughness 0.20 with procedural variation 0.15–0.28 plus fine-grain bump. SPEC table updated to match. Going forward, materials reference is the canonical source; SPEC describes the scheme, not the numbers.
- **2026-04-25:** Asset rendering pipeline is Python scripts in `scripts/blender/` invoked headless via `/Applications/Blender.app/Contents/MacOS/Blender --background --python <script>`. The Blender MCP server route attempted in the prior session did not work out. Python scripts are versioned, deterministic, and check in cleanly — the MCP attempt left no committable artifacts. Two-line invocation, full reproducibility.
- **2026-04-25:** `assets/blender/**/*.blend` and `scripts/blender/**` now tracked in git. The previous gitignore ignored the entire `assets/blender/` tree, which silently lost the prior asset session's work — committed nothing was committed because nothing could be added. Selective ignores added for `.blend1`/`.blend2` autosaves and exploratory PNGs (`_smoke_test*`, `bar_test_*`, `coin_test*`, `grain_test*`).
- **2026-04-26:** Blender-rendered sprites bake intrinsic transparent margin into the PNG at render time, not via downstream CSS padding. Target framing is ~65–70% canvas occupancy on the longest axis with clear transparent border on all four sides. Sprites authored edge-to-edge are a defect: they truncate visibly the moment a container clips or a CSS scale grows the sprite past its frame, and no amount of container padding restores edges that aren't in the file. Ground rule established by the gold cube re-render — the original `dist=1.0` framed the cube flush against the canvas; pulling back to `dist=1.55` produced 65.6% × 67.4% occupancy with margins L245 T331 R305 B191 px on the 1600 × 1600 canvas. Same rule applies to the upcoming animal/zoo references and any future commodity sprites.
- **2026-04-26:** Commodity panel layout widens at desktop breakpoints (`md:` and up) to give the cube + reference visualisation more horizontal canvas, capped at 1400 px. The slider, date picker, and dollar readout column stay at `max-w-2xl` (672 px) — they're text-driven and gain nothing from extra width. Mobile (< 768 px viewport) unchanged: the panel keeps filling the viewport and the £1 coin renders at true 23.43 mm CSS-mm "actual size". On desktop, `CubeRenderer` lifts its `sceneScale` cap from 1.0 to 2.0 so the visualisation grows into the wider canvas instead of sitting stranded at true mm size. Single multiplier applied to both cube and reference preserves the relative scale ratio that's the whole point of cube mode.
- **2026-04-26:** `scripts/blender/gold_cube.py` is the canonical Blender pipeline pattern that subsequent reference, commodity, and zoo renders inherit: scene reset and orphan-mesh cleanup; HDRI world (`brown_photostudio_02_4k.exr` rotated 45°); three-light area rig at locked positions/energies (key 120 W warm, fill 60 W neutral, rim 40 W warm); three-quarter perspective camera (50 mm, 25° elevation, 30° azimuth, dist≥1.55 for intrinsic margin); Cycles CPU at 512 samples with denoising and Standard view transform; transparent-film PNG output at 1600 × 1600; separate shadow-catcher pass with `visible_camera = False` on the subject so the shadow PNG is shadow-only; `.blend` source saved alongside the sprites. Future animal renders should subclass this script's structure rather than re-deriving the rig.
- **2026-04-26:** Animal references render at 0.5 m longest dimension in Blender for lighting-rig consistency. Real-world size is tagged in `src/lib/scale-references.json` via `realSizeMetres`; the runtime renderer applies the size relative to the cube. The two values are deliberately decoupled — the lighting rig in `assets/materials-reference.md` is calibrated for a ~0.5 m subject and produces inconsistent specular/contact-shadow falloff if the subject is rendered at smaller real-world sizes. Mirrors the gold cube convention (cube authored at 0.5 m edge in Blender, CSS-scaled at runtime via `CubeRenderer`). Per-animal `measurementAxis` field on each `ScaleReference` entry tells the render script which bbox dimension to scale against (`height` for the Shiba; `length` for the bee/whale; `longest` is the default).
- **2026-04-26:** Shiba Inu implemented as the first entry in the animal reference library, both as a static sprite (rendered through the same Blender pipeline as the gold cube) and as an animated `.gltf` triggered via the easter egg. Easter-egg triggers: hover ≥200 ms (desktop), sustained tap ≥500 ms (mobile), or `?easter=doge` URL parameter. All three respect `prefers-reduced-motion: reduce` — when set, the static sprite always wins. `@google/model-viewer` and the .gltf are dynamically imported on first trigger so neither hits the network on initial page load. Pattern established here will be replicated for the other 11 animals (blue whale, sperm whale, humpback whale, elephant, horse, large dog, cat, mouse, bee, ant, flea) in a subsequent session — see `assets/references-attribution.md` for the queue.
- **2026-04-26:** `ScaleReference` schema gains two optional fields: `animatedModelPath?: string` (path to a .gltf for the easter-egg renderer; references without it stay static-only) and `measurementAxis?: "length" | "height" | "longest"` (read by the Blender render scripts; defaults to "longest" so the existing 19 silhouette entries don't need backfill). Both kept in `src/lib/scale-references.json` so the JSON is the single inventory of references — render scripts are parameterised templates that read the JSON entry's fields, not hardcoded per-animal scripts.
- **2026-05-04:** Cycling scale-reference library deleted. Single Shiba Inu (true 40 cm height, viewport-scaling camera) is the universal cube-mode scale reference, present on every cube-mode panel (gold, silver, Pu-238). Cocaine is the single exception — its forensic-still register is set entirely by the image. Reasoning: the cycling library was a meaningful asset-production cost and a source of register clashes between Kenney-style references and Blender-rendered cubes; the dog as universal cube-mode anchor is the cleaner solve, and concentrating the editorial-still treatment on cocaine alone keeps that exception meaningful rather than diluted.
- **2026-05-08:** Cube-mode viewport sized to the *larger* of (Shiba, cube) plus 10 % margin: `viewportHeightM = max(0.40, cubeEdgeM) × 1.10`. Both sprites render at true scale within that viewport — cube pinned to the left edge, Shiba to the right edge, both bottom-aligned. Reverses the prior framing where the dominant element was assumed always to be the cube and the Shiba would clip at low amounts. Reasoning: at 1 BTC the cube is ~24 mm and the Shiba is 400 mm; the half-row-fit rule had been forcing the larger element to fit within half the panel width, leaving both as specks with vast empty space around them. Sizing the viewport to the dominant element instead means whichever is larger fills its side; the other scales down proportionally. Honest at every slider position with no clipping.
- **2026-05-09:** Pu-238 meltdown visualisation specced for Stage 6. Above the geometry-corrected dissipation threshold the existing `CubeGlowOverlay` intensity gains a slow ~0.7 Hz sine modulation (5–10 % amplitude) and the contact-shadow under the cube shimmers in sync — the cube *appears to struggle to dissipate decay heat*, which is what real Pu-238 metal of that geometry would actually do before self-destructing. A small red status dot next to the brand-voice clarification and one terse line in the readout strip ("Decay heat exceeds dissipation — would self-destruct in seconds") complete the warning. `prefers-reduced-motion: reduce` kills the pulse and the heat-haze shimmer but keeps the colour state and copy, so the warning is legible without motion. Reasoning: a flashing-red overlay or sirens-style warning would betray the "honest, precise, slightly dry" brand voice and risk photosensitive-epilepsy concerns; modulating the existing glow + shadow keeps the warning *of* the visualisation rather than *on top of* it — and the modulation itself is honest physics. Threshold mass requires a geometry-corrected thermal calc (decay-heat dissipation vs. Pu's 640 °C melting point); single-digit-to-tens-of-grams territory for pure cube-form Pu-238, sharper if convection is suppressed.
- **2026-05-09:** Cube + Shiba layout finalised under iteration on staging. Edge-anchoring (2026-05-08) and centred-pair drafts both lost the relative-scale read; the keepers are: (1) **fixed midline anchors** — each element's *visible* bottom inner corner sits at midline ± `GAP_FROM_MIDLINE_PX`, never the transparent canvas edge, so a per-sprite `translateX` shifts the slot by its measured L/R-margin fraction to put the visible corner on the anchor line; (2) **`pxPerMetre` is visible-pixels-per-metre** — each slot is scaled by `1 / visibleHeightFraction` so the sprite's visible bounding box (not the transparent canvas) fills the viewport, no more empty headroom above the dog; (3) **row height is derived** from the dominant element's visible height × `VIEWPORT_MARGIN`, capped by a soft `clamp(min, 50vh, max)` — the row only consumes as much vertical space as the visible content needs, which matters most on mobile; (4) **gap is responsive** — 50 px desktop, 14 px below the 768 px breakpoint, since 50 px each side ate most of a narrow phone row; (5) **width clamp checks both cube and Shiba** — the cube's visible-width-to-height ratio (~0.98) is much higher than the Shiba's (~0.73), so at near-equal real heights (e.g. 1789 BTC of gold: cube 36.6 cm, Shiba 40 cm) the cube's width is the binding side even when Shiba is dominant by height; clamping only on the dominant element overflowed the cube off the panel. Sprite-margin constants (cube `R 19.0 % / B 11.9 %`, Shiba `L 30.4 % / B 24.8 %`, visible width/height fractions) are measured directly from the shipped asset files.
- **2026-07-10:** Fixed the live-scene bug where the Shiba's head was fully occluded behind the gold cube around 7,706 BTC (≈0.6 m cube edge). Root cause: `besidePlacement`'s `besideZ = edge * 0.45` sat the dog's origin slightly BEHIND the cube's front-face plane (edge / 2), and `LiveStage` rotates the dog to face the cube, leaning its head straight into the front-left camera's occlusion wedge — the failure band was roughly 0.5–1.2 m edge, empirically the whole ~2.5 cm–1.2 m range once checked with an exact segment-vs-cube test. New invariant: the whole dog — origin plus its nose reach (`DOG_NOSE_REACH_M`, derived from `DOG_TOTAL_HEIGHT_M`) along the ACTUAL facing ray `LiveStage` rotates it to — must provably clear the cube's occlusion wedge (an exact segment-vs-AABB slab test, `dogFullyClear` in `maths.ts`) at every edge, commodity, aspect, and point along the beside→foreground blend, not just at the two blend endpoints. Fix is sideways-first: `clearBesidePlacement`/`clearPointPlacement` clamp the origin in front of the cube's face (the root cause) then bisect a minimal +x push, preferring sideways over pulling the dog toward the camera (+z), because +z inflates apparent size and breaks scale honesty (guarded in tests: dog/cube camera-distance ratio stays ≥0.8 below 1.2 m). An early implementation sampled a blind 360° compass circle around the nose reach (robust to "any facing") instead of the true facing ray; it produced false positives against the signed-off small-cube "sniffing" shot and a real sub-millimetre-edge discontinuity, both traced to testing directions the model never actually occupies — sampling the known facing ray instead fixed both and is the shipped design.

## Process

- **2026-04-19:** Claude Code sessions are scoped per phase. Each phase gets a fresh session with a specific handoff prompt. Do not let sessions drift across phase boundaries.
- **2026-04-19:** Handoff prompts always begin with "read the spec and summarise your understanding of [specific sections] before writing code." Single most valuable insurance against session-long misreadings.
- **2026-04-19:** Small commits, one logical unit per commit, conventional commit messages (`feat:`, `chore:`, `docs:`, `test:`). Four clean commits read better than one "initial dump" both for credibility and future diffing.
- **2026-04-20:** API keys never appear in chat. Always set via `.env` file (gitignored) locally and repo secrets in GitHub. If Claude Code or Claude asks for a key value directly, that's a mistake — push back.
- **2026-04-26:** A session ends when `git log origin/main --oneline -5` shows the work, not when `git commit` succeeds. "Committed locally" is not done; "pushed to main" is done. Companion failure mode to the 2026-04-25 gitignore rescue: that one was *work happens but git refuses to track it* (silent drop at the working-tree → index boundary); this is *work is tracked locally but never reaches the remote* (silent drop at the local-repo → remote boundary). Same shape, different mechanism. The fix is the same shape too — confirm presence at the destination, not at an intermediate stage. Required final-step check on every session: fetch origin, run `git log origin/main --oneline -5`, and confirm the artefacts the session produced are visible on the line. If they aren't, the session isn't done.
